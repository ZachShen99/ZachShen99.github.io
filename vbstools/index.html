IntelliSense

COM 对象的补全COM object completion

直接读你电脑上注册的类型库。输入 CreateObject(" 会列出所有 ProgID，对象后面能补出方法和属性。 It reads the type libraries registered on your machine. CreateObject(" lists every ProgID, and objects complete their methods and properties.

  • 链式调用、For Each、With、默认成员、函数返回值，类型都能顺着推下去
  • Types follow through chains, For Each, With, default members and return values
  • 有参数提示和悬停说明
  • Parameter info and hover docs
  • 推断不出来的地方，用 ' @type 注释告诉它
  • Where inference can't tell, add a ' @type comment
Debugger

能下断点的调试器A debugger with breakpoints

按 F5 就能调，不用写 launch.json。Press F5. No launch.json to write.

  • 条件断点、命中次数、日志点；单步进入、跳过、跳出
  • Conditional breakpoints, hit counts, logpoints; step in, over and out
  • 变量、监视、调用栈；COM 对象能一层层展开
  • Variables, watch and call stack; COM objects expand level by level
  • 变量可以双击改值，调试控制台也有补全
  • Double-click a variable to change it; the Debug Console completes too
Diagnostics

边写边查错Errors as you type

语法错误交给系统自带的 vbscript.dll 去编译（只编译，不运行），所以报的错和真跑的时候一样。 Syntax errors come from the system's own vbscript.dll, which only compiles and never runs your script, so they match what a real run reports.

  • 没声明的变量、不存在的过程、参数个数不对、没用到的变量
  • Undeclared variables, unknown procedures, wrong argument counts, unused variables
  • Ctrl+. 一键修复；F12 转到定义，Shift+F12 找引用，F2 重命名
  • Ctrl+. quick fixes; F12 go to definition, Shift+F12 find references, F2 rename
WinCC

自带 WinCC V7 / V8 对象模型WinCC V7 / V8 built in

有些脚本跑在软件内部，本机没有注册类型库。WinCC 的我已经内置了，HMIRuntime.Tags("x").Read、事件过程里的 Item. 都能补全。别的软件可以自己写一个 *.vbstypes.json 来描述。 Some scripts run inside another application, with no type library on your machine. WinCC is built in, so HMIRuntime.Tags("x").Read and Item. in event procedures complete. For other applications, describe them in a *.vbstypes.json file.

Code Library

代码库Code library

示例脚本可以先预览再插入。常用的代码存成自己的片段，输个缩写就展开。 Preview sample scripts before inserting them. Save the code you reuse as snippets and expand them with a short trigger.

Encoding

不再乱码No more garbled text

cscript 只认 ANSI 和 UTF-16。ANSI 的脚本会按系统代码页打开；带中文的 UTF-8 脚本，会提示你一键另存。自带的脚本宿主输入输出中文、日文、emoji 都没问题。 cscript only reads ANSI and UTF-16. ANSI scripts open with the system code page, and UTF-8 scripts with non-ASCII text get a one-click re-save. The bundled script host reads and writes any Unicode, emoji included.

类型库 + 类型推断Type libraries + inference

从 ProgID 找到注册表里的类型库，读出里面的成员，再顺着你的代码往下推：fso → Folder → Files → File。 From a ProgID to the registered type library and its members, then along your code: fso → Folder → Files → File.

只编译，不运行Compile, never run

语法检查直接调 vbscript.dll 的解析器，脚本引擎根本不会启动。 The syntax check calls vbscript.dll's own parser. The script engine is never started.

自己写的脚本宿主My own script host

cscript 没有调试接口，所以我从头写了一个兼容的宿主：加载系统的 vbscript.dll，WScript 对象自己实现，和 cscript 逐项对照测过（Native AOT，x64 / x86 各一个）。调试时在每条语句前插一个钩子，行号不变，脚本里的 On Error 处理不受影响。 cscript has no debugging interface, so I wrote a compatible host: it loads the system's vbscript.dll, implements WScript from scratch and was tested against cscript (Native AOT, x64 and x86). Debugging puts a hook before every statement, so line numbers stay put and your On Error handling is left alone.
